# ADR-0009: Replace the public dashboard link with signed, time-limited embedding

- **Status:** Accepted
- **Date:** 2026-11-18

## Context

ADR-0006 embedded the agent's dashboard via Metabase's public sharing: a permanent, guessable
link (a UUID) that needs no sign-in, which anyone who learns it can open forever. That ADR
flagged this explicitly as acceptable only for a single local user, to revisit otherwise. This
revisits it: not because the project is exposed anywhere yet, but because the gap was clearly
named and the fix (Metabase's signed/static embedding, same mechanism, same amount of code) is
no harder than what was already there.

## Options considered

1. **Keep the public link** - nothing to build, but every dashboard the agent ever creates
   stays viewable by anyone with its link, forever, with no way to expire it short of turning
   public sharing off for the whole instance.
2. **Metabase's signed (static) embedding** - a server-side secret signs a short-lived JWT
   (`{"resource": {"dashboard": id}, "exp": ...}`) per view; the iframe's `src` is
   `/embed/dashboard/<token>`. No standing link exists: a token not generated by this code,
   or one that has expired, shows nothing.

## Decision

Switch to signed embedding. `agent/dashboard.py`:

- `ensure_embedding_secret()` generates Metabase's `embedding-secret-key` once (if not already
  set) and turns on `enable-embedding-static`, both via the admin API, matching how the rest of
  this app configures Metabase - no manual admin-UI step.
- Each dashboard this app creates gets `enable_embedding: true` set on it.
- `Dashboard.embed_url()` signs a fresh token (10-minute lifetime) with `PyJWT` on every call,
  rather than returning a stored link - the embedded iframe already gets a new `src` on every
  Streamlit rerun, so a fresh token each time costs nothing extra and needs no token-refresh
  logic.
- Public sharing (`enable-public-sharing`) is turned off; the dashboards made public while
  testing ADR-0006 are no longer reachable by their old links.

## Consequences

- No link to a dashboard this app made works on its own; a screenshot of the iframe's URL is
  useless after ten minutes, and useless immediately to anyone who isn't running this code.
- One more dependency (`pyjwt`), and one more Metabase setting (`embedding-secret-key`) this
  app owns and must not lose - if it ever needs rotating, old tokens just stop working, which
  is the intended failure mode.
- `Dashboard.embed_url` changed from a property to a method (it does real work - signing - on
  every call); the one caller (`agent/app.py`) was updated to call it.
- Still a personal/local-only story: the secret lives in the Metabase instance this app
  configures itself, not in a vault, which is fine as long as that instance is Ondra's own.
